Sorted by Name, “Photo 2.png” sits before “Photo 10.png” — the way the Finder does it, and the way a naïve lexicographic sort doesn’t. That’s MAFinderComparator, and it’s the default.

Batteries included. You opt out, not in.

The distance between an austere list and a mac-assed one is one type name and one autosave string. Everything above — sort, reverse, ⇧/⌘ multi-select, type-select, keyboard nav — is on by default.

Before — plain SwiftUI
List(files, selection: $selection) { file in
    Text(file.name)
}
// austere. nothing sorts. nothing
// remembers. one thing selects.
After — MacAssed
MATable(files, selection: $selection) {
    MAColumn("Name", value: \.name)
    MAColumn("Size", value: \.size,
             align: .trailing)
}
.columnAutosave("Files")  // remembered

/ Lost & Found · the deepest cut

Spatial memory — put it there, it stays there.

The classic Finder was spatial: one window per folder, each reopening where you left it, every icon exactly where you put it. You navigated by muscle memory. John Siracusa has argued the case for decades. Drag these icons around — then reload the page and find them where you left them.

Projects
drag an icon anywhere — it remembers

Clean Up snaps to the grid without reordering; Arrange by Name reflows a sorted grid; Reset Layout undoes the arrange, because a hand-placed layout is precious. Icon positions are content-relative, so they’re display-independent — they survive a monitor change untouched; only window placement carries the multi-display asterisk. In MacAssed this is MASpatialView — opt-in, because it’s native by default, nostalgic by choice.

/ Tools

Things MacAssed gives you to put them back.

The behavior lives in a UI-free core you can test on Linux; the SwiftUI views are a thin layer on top. And the whole thing carries one coherent identity — the MA prefix, revived on purpose.

MATablethe flagship — sortable, multi-select, self-persisting
MAListthe one-column sibling; the right call on iPhone
MASortthe primary → secondary sort stack
MASortDescriptorone persistable sort level (yes, after NSSortDescriptor)
MAFinderComparatornumeric-aware ordering that sorts like a Mac
MASelectionthe ⇧/⌘/marquee/arrow selection grammar, as a model
MAColumnLayoutorder, widths, visibility — Codable, reconcilable
MAViewStateone autosave name; the window comes back
MACommandsSort By ▸, Select All, Invert — the menus SwiftUI skips
MAChromeopt-in Platinum / Aqua skins, never kitsch
MAOutlineexpand-all, persisted disclosure
MAInspectorGet Info, multi-value editing

On the name — and the MA prefix

A Mac-assed Mac app is a running term of art: an app that wholeheartedly embraces the platform instead of settling for a lowest-common-denominator port. Coined by Collin Donnell, popularized by Brent Simmons, used by Gruber since 2020. We put the link in the README, so the homage is self-sourcing.

And the prefix is a small joke that means it. Old Apple frameworks prefixed types — NS, UI, CG, MK — because Objective-C had no namespaces. Swift made that “unnecessary,” and the prefixes vanished in the same cultural moment the UI conventions did. So MacAssed brings the prefix back. The branding does the thing the library does — recovers a good convention dropped for looking old-fashioned. The module is MacAssed; the types are MA… — exactly Foundation’s relationship to its NS… types.

v0.4

v0.5

Text & undo.

MATokenField · MAComboBox · MAField editor bindings · MAUndo named actions.

MacAssed

Design sketch · pre-alpha. A settled API shape with illustrative bodies. The plan is real; the MacAssedCore behavior is described by tests. A renaissance has to start somewhere.
